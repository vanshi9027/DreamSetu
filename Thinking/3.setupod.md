# DreamSetu - Setu Pod Backend Thinking

## Feature

AI-Powered Setu Pod Formation

---

# Objective

Create balanced collaborative learning teams where students can build real-world projects together.

Each Setu Pod contains:

- 🌱 Beginner
- 🚀 Intermediate
- 🎯 Expert

---

# Backend Feature Thinking Framework (BFTF)

---

# Step 1 — Business Problem

## Why does this feature exist?

Students struggle to find teammates with complementary skills.

Problems:

- Beginners don't know whom to learn from.
- Experts don't have structured mentoring opportunities.
- Teams are often unbalanced.
- Students learn alone.

DreamSetu solves this by automatically creating balanced learning teams.

---

# Step 2 — Actor

## Who uses this feature?

### Student

- Clicks "Find My Pod"
- Joins assigned pod
- Collaborates on projects

### Backend

- Finds compatible students
- Creates Setu Pod
- Stores pod information

### Admin

- Monitors pods
- Manages pods when necessary

---

# Step 3 — Goal

Student wants to:

- Join a balanced learning team
- Build real-world projects
- Receive personalized tasks
- Learn from teammates

Backend goal:

Create a balanced Setu Pod.

---

# Step 4 — Required Data

Backend needs:

- User
- Skill Level
- Preferred Domain
- Preferred Language
- Weekly Availability

Most of this already exists in the user's profile.

---

# Step 5 — Existing Data

Already available:

- User ID (JWT)
- Full Name
- Email
- Skill Level
- Preferred Domain
- Preferred Language
- Weekly Availability
- Profile Status

Frontend doesn't need to send these again.

---

# Step 6 — Authentication

Student must be logged in.

Reason:

Backend needs

- User ID
- Skill Level
- Domain
- Language

These are fetched using JWT.

---

# Step 7 — Validation

Before creating a pod:

✅ User logged in

✅ Profile completed

✅ Skill Assessment completed

✅ User not already in an Active Pod

✅ Compatible teammates available

---

# Step 8 — CRUD Operations

Workflow:

READ

↓

Validate

↓

CREATE

Backend first:

- Reads current user
- Reads compatible users

Finally:

Creates Setu Pod

---

# Step 9 — Collections

Read

- Users

Write

- Pods

Projects and Tasks will be separate modules.

---

# Step 10 — Relationships

Members should reference Users.

Example

members:

- user
- role

instead of storing

- name
- email
- college

Reason:

Avoid duplicate data.

---

# Step 11 — Success Response

Frontend should receive:

- Success
- Message
- Pod ID
- Pod Name
- Members
- Status

Example

{
success: true,
message: "Pod created successfully",
pod: { ... }
}

---

# Step 12 — Failure Responses

Possible failures:

401 Unauthorized

Profile incomplete

Assessment not completed

Already in Active Pod

No matching teammates found

Database Error

---

# Matching Strategy

Priority:

1. Skill Level
2. Preferred Domain
3. Availability Overlap
4. Preferred Language

Availability should not require an exact match.

Use overlap instead.

---

# While Waiting

Never leave students idle.

Instead:

- AI Daily Tasks
- Coding Challenges
- Learning Resources
- Community Discussions

Learning continues while matching runs.

Return existing pod

---

Continue AI learning

---

---
